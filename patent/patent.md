# 一种融合 DOM 语义解析与智能决策的测试自动化执行方法及系统

## 摘要

本发明公开了一种融合 DOM 语义解析与智能决策的测试自动化执行方法及系统，属于软件测试技术领域。该方法包括：加载目标网页并构建页面语义表示，通过语义解析器对页面 DOM 元素进行抽象映射，生成具有语义信息的元素引用标识；接收用户输入的测试任务描述，通过语义分析提取任务中的关键实体和操作意图；基于推理 - 行动交替循环架构执行测试任务，将当前页面语义表示和对话历史构建为提示消息，调用预训练的决策模型生成推理响应，解析推理响应并执行相应的页面操作，获取观察结果并追加到对话历史中，进入下一轮循环直至任务完成；将整个执行过程中记录的操作序列进行后处理，生成标准化的测试脚本。本发明通过 DOM 语义解析与智能决策的融合，实现了无需预先编写脚本即可完成复杂测试场景的自动化执行，显著降低了测试脚本的维护成本，提高了测试用例的适应性和执行效率。所述系统包括输入模块、处理模块、执行模块和输出模块，用于实现上述方法的各个步骤。

## 技术领域

本发明涉及软件测试技术领域，尤其涉及一种基于网页界面分析的测试自动化执行方法及系统，具体是一种融合 DOM（Document Object Model，文档对象模型）语义解析与智能决策的测试自动化执行方法及系统。随着 Web 应用的快速迭代和复杂度持续提升，自动化测试在软件质量保障中发挥着日益重要的作用。然而，传统的 Web 自动化测试方法主要依赖于预先录制的脚本或基于固定选择器的元素定位方式，在应对频繁变化的页面结构时，普遍存在脚本维护成本高、适应性差等局限性。为此，本发明提出了一种创新的测试自动化执行方法及系统，通过 DOM 语义解析与智能决策的深度融合，实现了测试任务的智能化自动化执行。

## 背景技术

在现有的 Web 应用测试领域，自动化测试技术已经得到广泛应用。目前主流的自动化测试方案主要包括以下几类：第一类是基于录制 - 回放的测试方法，该方法通过记录用户在浏览器中的操作步骤，生成可重放的测试脚本，代表性工具包括 Selenium IDE、UI.Vision 等，其优点是使用简单，无需编程经验，但缺点是生成的脚本缺乏灵活性，当页面元素发生微小变化时，脚本往往无法正常运行，需要人工介入修改。第二类是基于固定选择器的测试方法，该方法通过 XPath、CSS 选择器等定位页面元素，编写测试脚本执行操作，其优点是脚本表达能力强，可处理复杂测试场景，但缺点是对页面结构变化敏感，当元素的 XPath 或 CSS 路径发生变化时，需要重新定位并修改脚本，维护成本较高。第三类是基于图像识别的测试方法，该方法通过图像匹配技术定位页面元素，代表性工具包括 Sikuli、Eggplant 等，其优点是不依赖页面 DOM 结构，可测试任何可见界面，但缺点是执行速度较慢，对屏幕分辨率和界面缩放比例敏感，且难以处理动态内容。第四类是基于机器学习的测试方法，近年来，一些研究开始探索将机器学习技术应用于测试自动化，如通过训练模型识别页面元素类型、预测用户操作等，该类方法在一定程度上提高了脚本的适应性，但通常需要大量标注数据进行训练，且泛化能力有限。

上述现有技术存在的共同问题是：脚本维护成本高，无论是录制回放还是基于选择器的方法，都需要在页面结构变化时手动更新脚本，对于大型 Web 应用而言，这是一项繁重的工作；适应性差，现有方法难以应对动态生成的页面内容、A/B 测试导致的界面差异、以及跨浏览器兼容性问题；测试覆盖有限，由于脚本编写和维护的成本限制，很多边缘场景和异常流程难以被充分测试；对测试人员技能要求高，编写和维护自动化测试脚本需要编程能力和对测试框架的深入理解，这限制了自动化测试的普及。因此，亟需一种能够自动理解页面结构、智能决策测试操作、并生成可维护测试脚本的自动化执行方法及系统，以解决现有技术中存在的上述问题。

## 发明内容

针对现有技术中存在的上述问题，本发明要解决的技术问题是提供一种融合 DOM 语义解析与智能决策的测试自动化执行方法及系统，该方法能够自动理解网页 DOM 结构，无需人工预先定义元素定位规则；能够根据自然语言描述的测试任务，智能决策执行步骤和操作序列；能够动态适应页面结构变化，降低脚本维护成本；能够自动生成可重放的测试脚本，支持后续回归测试；能够在执行过程中捕获网络请求详细信息，支持前端接口性能分析。

为解决上述技术问题，本发明采用如下技术方案：

本发明提供了一种融合 DOM 语义解析与智能决策的测试自动化执行方法，包括以下步骤：步骤 S1，加载目标网页并构建页面语义表示，启动浏览器驱动，加载目标网页 URL，遍历网页的 DOM 树结构，提取每个可见元素的属性信息，所述属性信息包括元素类型、文本内容、层级路径、可操作状态，为每个可操作元素分配唯一的引用标识，建立 DOM 元素与引用标识之间的映射关系，生成当前页面的语义表示快照；步骤 S2，解析测试任务并生成任务意图表示，接收用户输入的测试任务描述，所述测试任务描述为自然语言文本或结构化指令，对测试任务描述进行语义分析，提取任务中的关键实体和操作意图，所述关键实体包括目标页面、操作对象、期望结果，将任务意图表示为中间格式，用于后续的操作生成；步骤 S3，基于推理 - 行动交替循环架构执行测试任务，将当前页面语义表示和对话历史构建为提示消息，调用预训练的决策模型生成推理响应，所述推理响应包括思考字段、动作字段和动作输入字段，解析所述推理响应，当动作字段指示完成指令时退出循环，否则从工具注册表中查找所述动作字段对应的工具并执行页面操作，获取观察结果和页面状态变化信息，将所述观察结果追加到对话历史中，返回执行下一轮推理 - 行动循环；步骤 S4，生成并输出测试脚本，将整个执行过程中记录的操作序列进行后处理，合并冗余步骤，优化元素定位表达式，生成标准化的测试脚本，所述测试脚本可在支持浏览器自动化框架的环境中独立执行，输出执行日志，包括操作步骤、执行时间、成功或失败状态、截图快照。

在一个实施例中，所述步骤 S3 中基于推理 - 行动交替循环架构执行测试任务，具体包括：在每次循环中，首先通过语义解析器获取当前页面的 DOM 语义表示快照，所述快照包含页面中所有可操作元素的引用标识及其属性信息；然后将所述引用标识与任务意图进行匹配，识别与当前任务相关的候选元素集合；接着调用决策模型对候选元素集合中的每个元素进行评估，生成包含思考、动作和动作输入的推理响应；最后执行所述动作并捕获执行后的页面状态变化和观察结果，将所述观察结果追加到对话历史中作为下一轮循环的上下文输入。

在一个实施例中，所述方法还包括网络请求监控步骤：在执行每个页面操作时，通过浏览器驱动的拦截机制捕获当前页面产生的所有网络请求，所述网络请求包括请求 URL、请求方法、请求头、请求体、响应状态码、响应头、响应体以及请求耗时；将所述网络请求信息与当前执行步骤的操作记录进行关联存储，形成操作 - 请求对应关系表；在任务执行完成后，基于所述操作 - 请求对应关系表生成前端接口性能分析报告，所述报告包括各接口的平均响应时间、最大响应时间、最小响应时间、请求成功率统计信息。

在一个实施例中，所述步骤 S4 中生成标准化的测试脚本，具体包括：将整个执行过程中记录的操作序列按照时间顺序进行排列，去除冗余的重复操作，合并连续的相同类型操作；根据操作序列中每个步骤的动作类型和参数，生成对应的浏览器自动化框架代码，所述浏览器自动化框架包括 Playwright、Puppeteer、Selenium；为每个生成的代码步骤添加等待和断言逻辑，确保脚本执行时的稳定性和可验证性；将生成的代码按照目标编程语言的语法规范进行格式化，输出为可独立执行的脚本文件，所述脚本文件可直接用于后续版本的回归测试。

在一个实施例中，所述方法还包括上下文压缩步骤：在执行循环过程中，动态维护执行历史上下文，当对话历史长度超过预设阈值时，对早期对话进行摘要压缩，保留最近 N 轮对话记录和关键的推理 - 行动 - 观察三元组，所述三元组包括智能体的思考内容、执行的动作类型、以及动作执行后的观察结果；通过正则表达式提取对话历史中的关键信息，所述关键信息包括涉及的文件路径、使用的工具名称、遇到的错误信息、已完成的操作；将压缩后的上下文继续用于后续循环的推理输入，以支持更长时间的任务执行。

与现有技术相比，本发明具有以下有益效果：第一，降低脚本维护成本，本发明通过 DOM 语义解析和动态元素映射，使测试脚本不依赖于固定的元素定位表达式，当页面结构发生变化时，系统能够自动重新建立元素映射关系，无需人工修改脚本，显著降低了维护成本。第二，提高测试适应性，本发明能够根据自然语言描述的任务自动推导执行步骤，无需预先编写详细的测试脚本，同一任务描述可适应不同版本的页面结构，也可在不同浏览器环境中执行，具有良好的跨平台适应性。第三，扩展测试覆盖范围，由于降低了脚本编写和维护的门槛，测试人员可以更轻松地创建大量测试用例，覆盖更多业务场景和边界条件，同时，智能决策机制能够探索人工可能忽略的操作路径，发现潜在的缺陷。第四，提升测试效率，本发明将测试任务的抽象描述直接转换为可执行操作，省去了传统方法中脚本编写、调试、维护的时间，测试人员可以将精力集中在测试场景设计上，而非脚本实现细节上。第五，支持回归测试，本发明自动生成的测试脚本可在后续版本中重复执行，支持回归测试，由于脚本基于语义化元素引用，相比传统脚本具有更好的稳定性，减少了回归测试过程中的误报。第六，提供性能分析能力，本发明通过网络监控模块捕获执行过程中的所有网络请求，可生成前端接口性能分析报告，帮助开发人员识别性能瓶颈和优化点。

在一个示例性的实施例中，如图 1 所示，提供了一种融合 DOM 语义解析与智能决策的测试自动化执行系统 100，该系统 100 包括输入模块 101、处理模块 102、执行模块 103、输出模块 104 和网络监控模块 105。输入模块 101 与处理模块 102 连接，处理模块 102 与执行模块 103 连接，执行模块 103 分别与输出模块 104 和网络监控模块 105 连接。输入模块 101 用于接收用户输入的测试任务描述，具体地，输入模块 101 接收用户以自然语言形式描述的测试任务，例如"打开某银行网站首页，点击导航栏中的基金链接，在产品筛选区域选择投资类型为股票型、风险等级为 R4 中高风险，查询符合条件的基金数量"，输入模块 101 还负责解析用户输入中的关键信息，包括目标 URL、期望执行的操作类型、预期的操作结果等，在实际应用中，输入模块 101 可以通过图形用户界面接收用户输入，也可以通过应用程序接口接收来自其他系统的输入。处理模块 102 是本发明的核心模块，包括语义解析器、决策引擎和状态跟踪器，语义解析器负责对网页 DOM 元素进行抽象映射，生成具有语义信息的元素引用标识，决策引擎负责根据当前页面状态和任务意图通过推理 - 行动交替循环架构选择最优操作，状态跟踪器负责记录操作序列及页面状态变化并维护任务执行进度，处理模块 102 可以部署于客户端或服务端，也可以部分部署于客户端、部分部署于服务端，具体部署方式可以根据实际应用场景进行调整。执行模块 103 用于根据处理模块 102 生成的操作指令驱动浏览器完成页面交互，执行模块 103 包括浏览器驱动、元素定位器和动作执行器，浏览器驱动采用 Playwright 浏览器自动化框架，支持 Chromium、Firefox、WebKit 等多种浏览器内核，元素定位器负责根据元素引用标识在页面中查找目标元素，动作执行器负责执行具体的页面操作包括点击、输入、选择、滚动等。网络监控模块 105 用于在执行每个页面操作时，通过浏览器驱动的拦截机制捕获当前页面产生的所有网络请求，将网络请求信息与当前执行步骤的操作记录进行关联存储，形成操作 - 请求对应关系表，并基于操作 - 请求对应关系表生成前端接口性能分析报告。输出模块 104 用于在任务完成后输出测试脚本和执行日志，输出模块 104 将整个执行过程中记录的操作序列进行后处理，生成标准化的 JavaScript 测试脚本，同时输出详细的执行日志，包括操作步骤、执行时间、成功或失败状态以及页面截图快照，输出模块 104 还可以输出网络性能分析报告，包括各接口的平均响应时间、最大响应时间、最小响应时间、请求成功率统计信息，输出模块 104 可以将测试脚本和性能报告存储于本地文件系统，也可以上传至版本控制系统或测试管理平台。

参考图 2，本发明提供的测试自动化执行方法采用 ReAct（Reasoning-Acting，推理 - 行动）架构，通过推理和行动的交替循环逐步完成任务，包括以下步骤，
步骤 S201，开始，系统初始化，加载必要的配置信息和浏览器驱动，具体地，系统启动时读取配置文件，配置文件包括 MCP 服务器配置、浏览器类型配置、最大迭代次数配置、上下文压缩阈值配置等，系统启动 MCP 管理器，MCP 管理器根据配置文件启动一个或多个 MCP 服务器，每个 MCP 服务器提供一组浏览器自动化相关工具，MCP 管理器将所有可用工具注册到工具注册表中，供后续步骤使用，系统启动浏览器驱动，浏览器驱动可以是 Playwright、Puppeteer、Selenium 等浏览器自动化框架，系统初始化日志记录器，用于记录执行过程中的关键事件和状态变化，系统初始化对话历史列表，用于存储 ReAct 循环过程中的推理和行动记录。

步骤 S202，加载目标网页，执行模块 103 通过浏览器驱动访问目标 URL，加载待测试的网页，具体地，执行模块 103 接收目标 URL 参数，调用浏览器驱动的导航方法访问目标网页，浏览器驱动启动浏览器实例，创建新的浏览器上下文和页面对象，向目标 URL 发送 HTTP 请求，接收服务器响应并渲染页面，在页面加载过程中，浏览器驱动监听页面加载事件，包括 DOM 内容加载完成、页面资源加载完成、网络空闲等状态，当页面达到稳定状态后，执行模块 103 通知后续步骤开始执行，在实际应用中，步骤 S202 可以包括超时处理机制，当页面加载超过预设时间阈值时，系统可以抛出超时异常或尝试重新加载。

步骤 S203，构建页面语义表示，语义解析器遍历加载页面的 DOM 树结构，提取每个可见元素的属性信息，包括元素类型、文本内容、层级路径、可操作状态等，语义解析器为每个可操作元素分配唯一的引用标识，建立 DOM 元素与引用标识之间的映射关系，生成当前页面的语义表示快照。

如图 3 所示，本发明通过三层结构实现 DOM 语义映射与操作定位，具体包括网页 DOM 树 301、语义映射层 302 和操作抽象层 303，网页 DOM 树 301 是浏览器渲染页面的基础结构，包括 html 根节点、body 节点 3011 以及多个子元素节点如元素 A3012、元素 B3013、元素 C3014 等，语义映射层 302 负责将 DOM 树中的每个可操作元素映射为语义化的引用标识，例如元素 A 映射为引用标识 E1(3012)、元素 B 映射为引用标识 E2(3013)、元素 C 映射为引用标识 E3(3014)，通过这种映射关系，系统将复杂的 DOM 路径表达式简化为语义化的元素引用，操作抽象层 303 基于语义映射层生成的引用标识，将用户操作抽象为标准化的动作指令，例如点击 (E1)3012、输入 (E2,"值")3013、选择 (E3)3014 等，这种分层设计使得测试脚本不依赖于具体的 DOM 路径，当页面结构发生变化时，只需更新语义映射层的映射关系，而无需修改操作抽象层的指令。

具体地，语义解析器从浏览器驱动获取页面的 DOM 树，从根节点开始深度优先遍历 DOM 树，对于每个元素节点，判断其是否为可见元素，判断标准包括元素是否隐藏、是否透明、是否在视口外等，对于可见元素，提取其元素类型，例如按钮、链接、输入框、下拉框等，提取其文本内容，例如按钮上的文字、链接的标题等，提取其层级路径，例如从根节点到当前元素的路径，提取其可操作状态，例如元素是否可点击、是否可输入、是否可选中等，语义解析器为每个可操作元素分配唯一的引用标识，引用标识可以采用简单编号形式，例如 e1、e2、e3 等，也可以采用分层编码形式，例如 e1_2_3 表示第一层第二个元素的第三个子元素，语义解析器建立 DOM 元素与引用标识之间的映射关系，并将映射关系存储于内存中供后续步骤使用，语义解析器生成当前页面的语义表示快照，快照包括所有可操作元素的引用标识、属性信息以及元素之间的关系，语义表示快照可以用于后续的操作生成和状态比较，在实际应用中，语义解析器可以采用增量更新策略，当页面发生部分变化时，只更新变化的元素，而不是重新构建整个语义表示，从而提高效率。

步骤 S204，调用大语言模型进行推理，处理模块 102 构建包含系统提示词、对话历史和当前页面状态的提示消息，调用大语言模型生成推理响应，具体地，处理模块 102 构建提示消息，提示消息包括系统提示词和对话历史，系统提示词定义了智能体的角色、可用工具列表、输出格式要求等，对话历史包含之前所有 ReAct 循环中产生的推理、行动和观察记录，处理模块 102 调用大语言模型客户端发送提示消息，大语言模型根据提示消息生成推理响应，推理响应采用结构化格式，包括思考（thought）、步骤简称（step_abbreviation）、动作（action）和动作输入（action_input）四个字段，思考字段包含智能体对当前状态的分析和对下一步行动的推理，步骤简称字段用于标识和跟踪进度，动作字段指定要执行的工具名称，动作输入字段包含工具执行所需的参数，在实际应用中，处理模块 102 可以对大语言模型的响应进行解析和校验，确保响应格式正确，如果解析失败，处理模块 102 生成错误观察并添加到对话历史中，进入下一轮循环。

步骤 S205，解析 AI 响应，处理模块 102 解析大语言模型返回的推理响应，提取动作名称和动作参数，具体地，处理模块 102 接收大语言模型返回的原始响应文本，尝试将响应文本解析为 JSON 对象，如果响应文本不是标准的 JSON 格式，处理模块 102 通过正则表达式提取 JSON 代码块，然后进行解析，处理模块 102 从解析后的 JSON 对象中提取动作名称、步骤简称、思考和动作输入，处理模块 102 验证提取的动作名称是否存在于可用工具列表中，如果动作名称不存在，处理模块 102 生成未知工具的错误观察，将错误观察添加到对话历史中，进入下一轮循环，在实际应用中，处理模块 102 可以对解析失败的情况进行容错处理，例如记录错误日志、生成友好的错误提示等。

步骤 S206，判断是否为完成指令，处理模块 102 检查解析出的动作名称是否为完成指令，具体地，处理模块 102 比较动作名称与预定义的完成指令标识，完成指令标识可以是 finish、task_complete 等，如果动作名称是完成指令，处理模块 102 提取动作输入中的最终答案，将最终答案添加到对话历史中，记录完成步骤信息，包括思考、步骤简称、动作、动作输入和观察结果，处理模块 102 返回任务执行结果，任务执行结果包括最终答案和所有执行步骤的详细信息，任务执行完成后，系统进入步骤 S210 结束流程，如果动作名称不是完成指令，处理模块 102 继续执行步骤 S207。

步骤 S207，调用工具执行操作，处理模块 102 根据动作名称查找对应的工具，调用工具执行页面操作，具体地，处理模块 102 从工具注册表中查找动作名称对应的工具对象，如果工具对象不存在，处理模块 102 生成未知工具的错误观察，将错误观察添加到对话历史中，进入下一轮循环，处理模块 102 检查动作输入参数的格式，动作输入参数必须是字典对象，如果动作输入参数是字符串或空值，处理模块 102 进行相应的格式转换或错误处理，处理模块 102 调用工具的执行方法，传入动作输入参数，工具执行方法在浏览器环境中执行具体的页面操作，包括点击元素、输入文本、选择选项、滚动页面、等待时间等，工具执行完成后返回观察结果，观察结果包括操作执行状态、页面变化信息、错误信息等，在实际应用中，工具执行可以包括异常捕获机制，当工具执行抛出异常时，捕获异常并生成错误观察，将错误观察传递给智能体进行反思和决策。

步骤 S208，获取观察结果和页面快照，处理模块 102 接收工具执行返回的观察结果，可选地获取页面快照，具体地，处理模块 102 接收工具执行方法返回的观察结果，观察结果可以是字符串格式或结构化数据格式，处理模块 102 将观察结果转换为统一格式的字符串，可选地，处理模块 102 调用页面快照方法获取当前页面的语义表示快照，页面快照包括当前 DOM 树的结构信息、所有可操作元素的引用标识和属性信息、当前 URL 等，页面快照可以用于后续的元素定位和状态比较，处理模块 102 将观察结果和可选的页面快照信息组合成完整的观察记录，在实际应用中，处理模块 102 可以对观察结果进行后处理，例如提取关键信息、生成摘要等，以减少 token 消耗。

步骤 S209，将观察结果追加到对话历史，进入下一轮 ReAct 循环，处理模块 102 将观察结果添加到对话历史中，准备进入下一轮推理和行动循环，具体地，处理模块 102 创建观察消息，观察消息包含观察结果和可选的页面快照信息，处理模块 102 将观察消息添加到对话历史列表中，对话历史列表按时间顺序存储所有的推理、行动和观察记录，处理模块 102 检查当前循环次数是否达到最大迭代次数，最大迭代次数是预设的循环次数上限，用于防止无限循环，如果未达到最大迭代次数，处理模块 102 返回步骤 S204，继续下一轮 ReAct 循环，如果已达到最大迭代次数，处理模块 102 可以生成任务未完成的观察结果，提示用户检查任务描述或页面状态，在实际应用中，处理模块 102 可以启用上下文压缩机制，当对话历史长度超过预设阈值时，对早期对话进行压缩，保留最近的对话记录和关键的推理行动观察三元组。

步骤 S210，结束，任务执行完成，输出模块 104 生成测试脚本和执行日志，具体地，输出模块 104 接收操作序列列表，操作序列列表包含所有执行的操作信息，输出模块 104 对操作序列进行后处理，后处理包括去除冗余操作、合并连续操作、优化元素定位表达式等，输出模块 104 生成标准化的测试脚本，测试脚本可以是 JavaScript 格式，适配 Playwright、Puppeteer 等浏览器自动化框架，测试脚本可以是 Python 格式，适配 Selenium、Requests 等测试库，测试脚本可以是通用中间表示格式，可以转换为不同目标语言的测试脚本，输出模块 104 将测试脚本写入文件，文件路径可以是用户指定的路径或系统默认路径，输出模块 104 生成执行日志，执行日志包括操作步骤、执行时间、成功或失败状态、页面截图快照等，输出模块 104 将执行日志写入日志文件或输出到控制台，在实际应用中，输出模块 104 可以提供测试脚本预览功能，供用户查看生成的脚本内容，输出模块 104 还可以提供测试脚本执行功能，供用户直接运行生成的脚本进行回放测试。

在一个示例性的实施例中，提供了一种上下文压缩机制，在长时间任务执行过程中，对话历史记录会占用大量 token，上下文压缩器维护对话历史记录，当对话轮数达到预设阈值时自动触发压缩操作，例如每 5 轮对话触发一次压缩，压缩操作采用以下策略，第一，保留系统消息，系统提示词始终保留，不参与压缩，第二，保留最近对话，保留最近 N 轮对话，默认 3 轮，确保智能体有足够的上下文理解当前状态，第三，压缩中间历史，将早期对话历史压缩为摘要信息，保留关键操作记录和状态转换信息，第四，提取关键信息，通过正则表达式识别和提取对话中的关键信息，包括涉及的文件路径、使用的工具名称、遇到的错误信息、已完成的操作等，压缩后的对话历史格式包括历史对话记录、用户消息摘要、助手消息摘要等，上下文压缩机制可以有效减少 token 消耗，支持更长时间的任务执行。

1. 一种融合 DOM 语义解析与智能决策的测试自动化执行方法，其特征在于，包括以下步骤：

   步骤 S1：加载目标网页并构建页面语义表示，启动浏览器驱动加载目标网页 URL，遍历网页的 DOM 树结构提取每个可见元素的属性信息，为每个可操作元素分配唯一的引用标识，建立 DOM 元素与引用标识之间的映射关系，生成当前页面的语义表示快照；
